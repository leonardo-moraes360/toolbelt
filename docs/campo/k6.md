## O que o tb pegou e o que deixou passar

**Pegou**
- Escopo do ticket alinhado ao diff (`drift` / `review.drift` limpos).
- Localização de `TagSet` / `MapTagSet` via `graph search` (útil para a issue).
- Abortar verify ao tocar `.toolbelt/thresholds.yaml` (path protegido hardcoded).
- Integridade do arquivo de invariantes (`mem check`).

**Deixou passar**
- Erro de build fora do `test_cmd` (verify PASS com árvore que não compila).
- Menção textual a `tests/hidden` tratada como violação (falso positivo), enquanto omissão de migrar `MapTagSet` não foi sinalizada (falso negativo de completeness).
- `guard.yaml` do operador sem efeito.
- Completeness da issue #2764 (API pública ok; adoção no consumer Prometheus RW e nota sobre `Map` não cobertas).
- Lint e suite completa do k6 (não orquestrados pelo default; config local apontou só `./metrics/`).

## Interação com instrumentação existente / onboarding

- k6 já tem `AGENTS.md` (+ `CLAUDE.md` symlink) com comandos canônicos (`make build/tests/lint/check`), arquitetura e regras de git.
- `tb init` **não lê** esses arquivos; cria `.toolbelt/config.yaml` genérico (`go test ./...` / `go test ./tests/hidden/...`).
- Ajuste manual: `verify.test_cmd: go test ./metrics/ -count=1` (suite full seria a do AGENTS, não a default do tb).
- `tb graph` **indexa** `AGENTS.md` como documento/seções (aparece em `graph.json`), mas isso não vira mandato/invariantes nem comandos de verify.
- `tb mem init` injeta invariantes genéricas anti-cheat que **não** vêm do AGENTS; possível duplicação conceitual (regras de teste do projeto vs regras tb) sem merge.
- Conflito potencial: AGENTS proíbe `git reset --hard` / force-push; o fluxo de estudo usou reset local para probes — o tb não alerta sobre políticas do AGENTS.
- O que o tb deveria importar: blocos de build/test/lint do AGENTS → `verify.test_cmd` / script de check; restrições de git e “all new code should have tests” → invariantes; mapa de packages-chave → seeds de `graph` / escopo de tickets.
